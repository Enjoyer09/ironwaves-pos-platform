01 / COMPONENTS

Actions

A solid fill for the next step. A quiet surface for supporting actions.

Ready to continue.

48px minimum target · 12px corner · 120ms press feedback. One primary action per region.

Text fields

Persistent labels, helpful hints and an error that explains how to fix it.

Used for order receipts. Demo only; nothing is sent.

16px input text avoids iPhone focus zoom · visible focus ring · inline error + aria-invalid.

Choices & preferences

Solid selected states. No barely visible tint-only selection.

Pickup selected.

Order notifications

48px radio and switch hit areas · arrow-key radio navigation · switch state exposed to assistive technology.

Product row

Product first. Price always visible. Add stays within thumb reach.

Consistent 62px artwork · aligned text · dedicated 48px add control. Artwork is illustrative, not a product photo.

Feedback

Messages pair meaning with an icon and text, not color alone.

Loading & empty states

Built on restraint.

03 / PATTERNS

Identify at the counter

  1. Scan your cardOne primary action on Home.
  2. Open a bottom sheetKeep the QR on a white surface in both themes.
  3. Present to the baristaReadable instructions + optional Wallet action.
  4. Receive server confirmationOnly then update stamps. Preview QR is non-scannable artwork.

Order a favourite

  1. Choose locationDisplay pickup branch before shopping.
  2. Browse or searchKeep product names and prices together.
  3. Review your bagShow quantity controls, subtotal and pickup information.
  4. Confirm explicitlyPreview stops at a demo confirmation; no payment or order is submitted.

Use an offer

  1. Understand the valueDiscount, eligibility and expiry visible.
  2. Read the conditionsUse a sheet instead of leaving the app.
  3. Check eligibilityExplain unavailable rewards with text.
  4. Confirm redemptionActual integration must verify on the server. Demo only confirms the preview state.

Accessible is the baseline.

04 / ACCESSIBILITY & iOS

Contrast pairs

Ratios computed from the token values using relative luminance. Normal text target: at least 4.5:1.

Foreground / backgroundLightDark

Raw brand orange is not used for small text on white. Disabled controls are intentionally muted and excluded from these passing pairs.

Larger text, without clipped actions

This sample demonstrates text reflow. It does not simulate the native iOS Dynamic Type API.

Your next coffee is closer.

Collect two more stamps to unlock a reward.

Do not disable pinch zoom in production. Avoid fixed-height text regions. Full screens still need testing with real device accessibility settings.

Interaction requirements

  • Focus: visible ring; sheets trap focus and return it to the trigger.
  • Screen readers: named icon controls, selected tabs, live feedback, form errors.
  • Motion: 120ms press feedback, 240ms transitions; no looping decoration. Honor reduced motion.
  • Touch: 48px hit targets; compact artwork lives inside a larger control.
  • Failure: preserve the bag on network/payment failure. Never credit a reward optimistically.

iPhone integration checklist

  • Safe areas: one owner for top and bottom insets. Avoid applying the bottom inset twice.
  • Keyboard: keep focused fields visible; let forms scroll, never cover the submit action.
  • Haptics: selection on tabs; success on confirmed reward; optional, not every touch.
  • Appearance: persist the preference on the customer root; do not change POS/admin tokens.
  • Wallet / push / Live Activity: native integrations remain separate from this HTML design demo.

Ready to build. Not yet deployed.

Customer-scoped tokens are included. No changes to authentication, orders, POS screens or the live iOS app.

05 / HANDOFF

Integration contract

Apply tokens to the customer root only. The theme attribute must be on the same element.

import './theme/design-tokens.css';

<div
  className="customer-design-system"
  data-customer-theme={theme}
>
  <CustomerApp />
</div>

/* Example component rules */
.customer-button {
  min-height: var(--c-touch-min);
  border-radius: var(--c-radius-control);
  background: var(--c-action);
  color: var(--c-on-action);
}

/* Apply insets once on the app shell. */
.customer-shell {
  padding-top: env(safe-area-inset-top);
  padding-bottom: env(safe-area-inset-bottom);
}

Design proposal only: this import is not present in the app. Migrate components gradually, then verify both customer entry points and theme states.
